# Управление секретами и процедура ротации (SOPS + age)

## 1. Модель безопасности
В репозитории Git хранятся исключительно зашифрованные файлы секретов: `secrets/*.enc.yaml`.
- Шифрование выполняется утилитой **SOPS** с использованием алгоритма **X25519** через **age**.
- Зашифрованы только поля `data` и `stringData`. Метаданные (имя секрета, неймспейс, ключи) остаются читаемыми для Code Review.
- Приватный ключ age хранится в `.state/age.key` или `~/.config/sops/age/keys.txt` и защищен правами `0600`.

---

## 2. Zero-Downtime ротация API-токенов (Dual-Token Pattern)

Традиционная смена токенов приводит к лавине ошибок 401 Unauthorized, пока клиенты обновляют свои заголовки. 
В нашем решении реализован двухфазный процесс ротации:

### Фаза 1: Активация переходного периода (`make secret-rotate`)
1. Генерируется новый криптостойкий токен.
2. Старый токен сохраняется в поле `API_TOKEN_PREVIOUS`.
3. Новый токен записывается в поле `API_TOKEN`.
4. Секрет шифруется и обновляется в Kubernetes.
5. Поды перезапускаются через `rollout restart`.
6. Сервис принимает **одновременно оба токена**.

### Фаза 2: Завершение ротации (`make secret-rotate-finish`)
1. После того как внешние клиенты перешли на новый токен, вызывается завершающий скрипт.
2. Поле `API_TOKEN_PREVIOUS` очищается.
3. Доступ по старому токену блокируется. Простоя клиентов не зафиксировано.
